# PTCGP Ranking / MARS v1.0.1

**Automatic completed-meta rollover and private canonical raw persistence**

Released: 2026-09-03

## What changed

v1.0.1 completes the operational automation of the Pocket **Latest Completed Meta**.

When the canonical expansion catalog detects a new current set, the previous set
can now be derived dynamically as the completed set. The production workflow
then derives its exact release window, performs canonical Limitless Tournament
API acquisition, freezes immutable raw evidence in private S3-compatible
storage, restores that evidence for exact zero-network OFFLINE replay, runs the
existing Core + MARS pipeline, validates the public bundle, and publishes the
result atomically.

The MARS methodology is unchanged.

## Automatic rollover

The production sequence is:

```text
expansion catalog refresh
        ↓
derive current + completed set
        ↓
derive exact canonical release window
        ↓
Tournament API LIVE acquisition
        ↓
validate and persist immutable raw privately
        ↓
restore frozen evidence
        ↓
exact OFFLINE replay
        ↓
Core + MARS
        ↓
produce and validate public bundle
        ↓
full regression
        ↓
stale-main guard
        ↓
one atomic publication commit
```

The workflow is fail closed. If any required stage fails, the existing Latest
Completed Meta remains published and repository state is not advanced.

## Private raw persistence

Canonical raw Tournament API evidence may contain player identifiers and is not
public data.

v1.0.1 adds a vendor-neutral S3-compatible object-store backend. The production
deployment uses a private Cloudflare R2 bucket, while the repository code remains
provider-neutral.

Credentials are supplied only through GitHub repository secrets. Raw evidence is
not committed, placed in the public bundle, or stored as a plaintext GitHub
Actions artifact.

## Safety and reproducibility

The rollover preserves the existing acquisition and MARS contracts:

- Limitless Tournament API is the only canonical Pocket production source.
- There is no silent legacy-HTML fallback.
- Release windows are derived from the canonical release catalog.
- LIVE `/tournaments` discovery remains fresh.
- Exact OFFLINE replay performs zero network calls.
- Raw evidence is hash validated.
- Public publication is restricted to the approved Latest Completed Meta files.
- Concurrent rollover runs are serialized.
- Publication aborts if `main` advances during the run.
- Existing public output remains intact on failure.

## Methodology

MARS remains source-agnostic and frozen for this release.

Production continues to use:

```text
Score_% = 100 * Phi(z_comp)
Z_PENALTY = 1.96
```

v1.0.1 changes acquisition persistence and completed-meta automation, not the
ranking formulas.

## Known limitations

- The first future real set-transition rollover has not yet occurred in
  production; the complete transition path has been validated through the
  deterministic shadow workflow.
- Cloudflare R2 is the current production object-store provider, while the
  storage interface intentionally remains S3-compatible and provider-neutral.
- The physical Pokemon TCG has not yet been generalized to the Tournament API
  acquisition architecture.
- MARS is an analytical ranking, not a tournament forecast.
